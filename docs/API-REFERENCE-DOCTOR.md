# API Reference - Doctor (`/api/doctor/*`)

Conventions that apply to every table below:

* Paths are shown with the mount prefix already applied (`/api` = `API_PREFIX`). Auth column: the role(s) admitted by `authenticate` + `authorize(...)`; "Public" = no `authenticate`. Rate limiting: every route also passes the global limiter (reads by a signed-in user: `READ_RATE_LIMIT_MAX` per user; writes and anonymous traffic: `RATE_LIMIT_MAX`); route-specific limiters are named in the "Validation / middleware" column.
* "body: X" / "query: X" / "params: X" name the Joi schema applied (`validate`, `validateQuery` -> `req.validatedQuery`). Unknown keys are stripped, values coerced; failures are `422 VALIDATION_ERROR` with `details` per field.
* Success envelope `{ success, message, data }`; errors `{ error: { message, code, details? } }`. Binary/stream routes (PDF, files) return the bytes directly.
* The tables were generated from the router source by a static scan (route registration order preserved within each file). Route-ordering caveat: where a literal path (e.g. `/order`, `/count`) shares a prefix with a `/:id` route the literal one is declared first in the source.

Every route below is guarded by `authenticate`, `authorize("doctor")`, `resolveDoctorId("self")` (sets `req.doctorId = req.user.id`). The same doctor controllers are re-mounted for admins under `/api/admin/doctors/:doctorId/*` (see the admin reference).

Notes on notable groups:

* **Onboarding**: `GET /onboarding` returns the checklist (6 steps; only `professional`, `specialties`, `documents` gate submit); `POST /submit` runs the same function as the guard. Required documents: degree certificate, ID proof, council registration.
* **Sessions / queue** (`doctorBooking`): `start | pause | resume | end | call-next`, cap via `PATCH /sessions/:id`; `bookings/:id/start-consult`, `skip`; `complete` (body `noShow`) writes status and queue_state in one transaction.
* **Prescriptions**: draft CRUD, `finalize` (rate limited by `pdfLimiter`, freezes template + clinical snapshot, then renders PDF outside the transaction), `amend` (new version), `sync-workbench` (refresh a draft from the Workbench consultation), `pdf`, and `bookings/:id/prescription`.
* **EMR** (`/doctor/emr/*`): read routes are patient-keyed and require a treating relationship (or consent); write routes go through a booking the doctor owns. `/emr/search/icd` queries the admin ICD master.
* **Record access**: `patient-search` (verified doctors only, limiter `patientSearchLimiter`), `access-requests` (limiter `accessRequestLimiter`), consented `records/:recordId/file` stream.
* **Analytics**: `/analytics/{overview,trends,patients,appointments,financial,quality,productivity,acquisition}`.
* The ten portfolio sections generated by a loop are listed after the tables.
